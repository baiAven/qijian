# 企见 · 企业红黑榜（网页试验版）

一个以本地副本为基础、共同记录企业工时、产品和供应关系的网页应用。使用 Yjs 与 y-indexeddb；无业务 API、无中心业务数据库。网页可以自行托管。本仓库不需要 Codex、Sites 账号或 OpenAI API Key。

## 欢迎参与

我们想让企业工时与产品背后的供应商信息更透明。项目仍处于早期网页试验阶段，欢迎补充可复查资料、校正历史记录、测试手机兼容性和改进代码。请先阅读 [贡献指南](CONTRIBUTING.md)。通过仓库的 Issues 提交问题或数据线索，Fork 后提交 Pull Request 参与开发。

**Local-first work-hours atlas with product and supplier traceability.** Built with React, Yjs, IndexedDB and WebRTC. Contributions in Chinese or English are welcome.

## 已有功能

- 企业红榜、企业黑榜，以及待补充 / 有分歧记录。
- 公司、产品、供应商关键词搜索；地区与行业筛选。
- 产品 → 品牌 / 供应商关系查询，各企业独立分类。
- 新增企业、工时记录、产品、供应关系。记录范围包含部门、日期、来源说明和可选来源 URL。
- 浏览器 IndexedDB 本地保存；同源标签页自动交换更新。
- WebRTC 手动交换邀请 / 回复码建立一对一直连；可选 Google STUN。无自动发现、无信令服务器、无 TURN 中继。
- 备份文件导出、导入并合并。离线新增记录可合并；重复导入幂等。

## 试用

1. 打开网站默认进入 GitHub 企业库；打开“显示示例”后，可在红黑榜体验虚构企业的产品与供应关系。
2. 搜索“键盘”，打开 Flow 无线键盘，查看品牌与供应商各自的分类。
3. 点击“补充信息”添加企业、工时、产品或供应关系。工时未知的企业也可保存。
4. 关闭“显示示例”查看自行补充的信息。
5. 右上角“本地副本”打开同步面板。两个设备依次交换邀请码、回复码；无法连接时，双方轮流导出并导入备份文件。

两个设备须访问同一版本。网页访问本身不会自动同步业务资料，双方需要配对或交换备份。

## 分类规则

- 红榜：记录为每周休息至少 2 天，且不加班。
- 黑榜：每周休息少于 2 天、每天工作至少 12 小时、两班倒，三项同时满足。
- 其他记录：待补充。
- 同一企业出现不同类别的记录：有分歧。不会静默用新记录覆盖旧记录。

这是试验版的产品规则，不是法律认定。所有真实用户记录均显示“待核验”，没有自动认证、投票认证或审核员。不同部门与日期的差异会保留，不能把历史线索当成整家公司当下的事实。当前不支持撤回 / 删除记录；更正采用追加方式。远端导入试图覆盖或删除本地既有记录会被拒绝。

## 去中心化的实际边界

- 本机搜索只覆盖本机已合并的资料，并非自动搜索全网。
- 连接对方意味着交换全部本地贡献。没有账户身份认证、数字签名、反女巫或反刷票能力，仅用于信任设备之间的小范围试验。
- 默认设备直连不使用 STUN，适合局域网尝试；开启后使用 Google 公共 STUN 获取连接候选地址。未配置 TURN，不能保证穿透运营商 NAT、防火墙或企业网络。
- 目前只能保持一个远端 WebRTC 连接；可以顺序连接多个设备，或用文件传播资料。不是大规模公共 P2P 网络。
- 手机后台、锁屏或关闭网页后不能保证继续运行。网页首次加载和刷新依赖网页托管；未实现 Service Worker 离线页面缓存，也未打包原生 App。
- IndexedDB 数据可能被清理，用户应导出备份。清除站点数据或更换域名不会自动迁移副本。
- 试验版备份数据约 1 MB、最多 5,000 条自定义记录，防止无限制导入。尚无附件 / 图片存储。
- 可适配常见手机屏幕，但并不保证每一款手机及浏览器均支持 WebRTC / IndexedDB。尚未完成 iOS / Android 真机和跨运营商联网验证。

## 运行与验证

需要 Node.js 22.13 或更高版本。

```sh
npm ci
npm run dev -- --host 0.0.0.0
npm test
npx tsc --noEmit
npm run lint
npm run build
```

本地默认地址以终端输出为准。localhost 是浏览器安全上下文；手机访问局域网 HTTP 地址可能无法使用 WebRTC、剪贴板或 crypto.randomUUID，手机试验请使用 HTTPS 站点。

测试覆盖分类边界、产品及供应商搜索、独立离线写入合并、重复导入、冲突保留、供应关系合并、恶意 URL 与非法引用拒绝、既有记录防删除、IndexedDB 恢复及同源标签页同步。IndexedDB 自动测试使用 fake-indexeddb；不等同于手机存储测试。WebRTC 真实传输需要另行真机验证。

## GitHub 企业库（2026-09-08 导入）

内置 318 个企业条目，来自 331 条原始记录：955.WLB 白名单 86 条、996.ICU 黑名单主表 235 条、996.ICU 白名单 10 条。同名项以保守的空白 / 大小写 / 括号规范化去重，13 条重复来源保留在对应企业的来源数组中；不推测品牌别名、母子公司或不同法律实体是否相同。某些原始条目本身包含部门或并列企业名称，318 是去重条目数，不是核验后的法律实体数。

默认打开“GitHub 企业库”并隐藏虚构示例，可按原始名单、城市、公司名搜索。原名单没有核实当前严格工时条件，所以不会自动填入已结构化工时报告；严格红黑榜仍依据本应用实际收到的工时报告。每条来源带原记录日期、名单文件更新时间、导入时间、固定提交版本的原文行链接，以及原文明确出现的工时关键词。记录未提供的日期标为“未提供”，没有把导入时间写成观察时间。996.ICU 黑名单主表之前的取消 / 争议表没有导入主名单。

公开来源索引随应用内置，不覆盖用户的本地贡献；同步给另一台设备前请确保双方打开此版或更新版本。导出备份只包含本地贡献，不重复导出内置资料。

导入清单：`data/github-import-manifest.json`；生成数据：`data/github-companies.json`。解析器为 `scripts/import-github.py`，输入需包含 `meta.json` 与按清单中的固定提交下载的三个原始 Markdown 文件。只导入事实字段和来源定位，不转载叙述性指控、员工截图或个人资料。产品、行业、供应商信息未在这些名单中提供，保持待补充。
